# Mirage Shield v1.3 研究レポート

対象: high-valley/Mirage-Shield、基準コミット `f39a0eb6938b9ebc65c04f7d41579a295ac21c8c`。2026年10月24日。

## 結論

応答予測型を追加したが、固定型を一般的に上回る結果は得られなかった。特定の探索役・条件では改善し、乱数型、モデルがずれる条件、囮の切替に時間がかかる条件では悪化する。現時点で既定方式として推奨できない。これは4入口の数理模型の結果であり、現実のサイバー攻撃や生成AIに対する防御性能を証明しない。

## 既存コード全体の調査

mainの追跡対象は `index.html` だけだった。HTML、CSS、シナリオ生成、6防御方式、2探索役、デモ、比較処理をすべて確認。旧版を `experiments/legacy-v1.2.html` にそのまま保存した。

- 同じシードでも乱数消費数が分岐する。randomは探索判定の乱数を消費せず、囮・命中ではhint乱数を消費しない。同じ初期条件という説明は正しいが、途中の偶然を方式間で対応させられず、対比較のばらつきを増やす。直ちに平均値の偏りを証明する問題ではない。
- 適応型は直近の選択頻度へ追従する一方、学習役は囮を見た入口を避ける。過去に多い入口が次も多いとは限らない。
- 固定Aは標的がAなら最後まで到達を防ぐ。移動型はその保護を手放す場合がある。A偏重は固定Aに有利、D偏重は不利。ラベルの対称性を検討せず1分布だけで優劣を論じるべきではない。
- 「重要度」は標的選択重みであり、損害額の加重評価には使っていない。重要度優先はlinked時にのみ有用な事前情報を持つ。A/D偏重の指定はlinkedを上書きする。
- cautiousは候補と固定Aの頻度差を閾値で比較する方式であり、期待防御利益を直接推定していない。guardもAへ戻るルールなので現配置に対する保守的更新とは異なる。
- 囮は探索を終了させない。16手を継続する。画面の「囮へ誘導されたら実標的に到達しない」は説明不足で、正確にはその手の到達だけを防ぐ。説明を修正した。
- 切替回数は表示するが費用も遅延も適用しない。固定1囮と移動1囮の容量は同じだが、運用費用の公平性は別問題。
- 1000回のみで区間推定がなく、画面で選んだ「未知条件」は独立検証ではなかった。シナリオ生成がDOMを直接読むため独立再現も難しい。同期の一括実行は端末の操作を止める。

## 実験設計

Python 3.12、標準ライブラリだけ。ネットワーク、実ホスト、攻撃ツール、生成AI APIは使用しない。生成するのは整数の入口ID、模擬応答、数値スコアのみ。

全方式は1手あたり同じ3個の乱数（探索判定・選択・雑音）を使用し、同じ初期標的・重要度・16手予算で比較する。防御なしだけ囮0、他は最大1。応答予測型も防御決定時には将来の乱数や隠れた標的位置、探索役の内部状態・種別を参照しない。履歴の応答から公称学習率0.48のスコアを再構成し、次の最大スコア入口を守る。同点は最小番号を選ぶという限界がある。予測値と入口Aのスコア差が選択閾値を超える時だけ移す。既存cautiousの「利益推定」とは異なり、こちらも経済的利益は評価しない。

防御: none / fixed / adaptive / risk / guard / cautious / predictive。
探索役: random（独立選択）、learning（旧版の点数学習）、sweep（A→B→C→D）、persistent（同じ入口を4手ずつ）。後2種は調整に使わない。

事前に `experiments/plan.json` に調整集合と検証集合を定義した。開発はuniform/A/D × random/learning、開始seed 31000000、各10000回。候補閾値0、0.1、0.3を比較し平均到達率で選択。採用値は0.1。`frozen.json` にエンジン・計画のSHA-256を記録した後、未使用条件を実行した。ホールドアウト読取後はアルゴリズムを変更していない。これは今回の作業内で分離した検証であり、第三者の盲検試験ではない。

検証は開始seed 91000000、各条件・探索役・方式10000回。B偏重、8手予算、雑音0.6/学習率0.2/探索率0.35、切替時1手囮無効、重要度連動。各条件は基準から個別に変更。乱数列はLCGで隣接シードを使っており、高度な独立性は保証しない。同じシナリオを条件間でも再利用するため各行を独立な証拠として合算しない。

区間は到達率のWilson 95%区間。固定型との差は同じseedの到達0/1の差から通常近似した対差95%区間。差が負なら固定型より到達が少なく、防御側に有利。多数の条件の同時検定補正はしていないため、区間は探索的な指標。全差が0の区間[0,0]はサンプル上の一致であり母集団での完全同等を保証しない。主評価は到達率。囮応答数、移動回数、使用手数も全JSONに記録するが、到達で早期終了するため露出時間が異なる。

## 実行規模と追試

閾値調整18万回、開発の全7方式42万回、旧版6方式再現12万回、ホールドアウト140万回、掲載対象は計212万回。旧版診断では未掲載の予測型も補助的に2万回計算しており、実計算は214万回。調整時の重複実行を含む数であり212万個の独立シナリオではない。画面テストの7万回は別枠。結果の全行とパラメータは `experiments/results/` のJSONを参照。

```
python -m unittest discover -s tests -v

node tests/legacy_parity.js
python -m tests.fair_fixtures > /tmp/mirage-fair.json
```

実験を再計算する場合はリポジトリのコピーで保存済み `experiments/results/` を退避してから次を実行する。凍結ファイルが存在すると開発段階の上書きを拒否する。既存成果を上書きせず比較すること。

```
python -m experiments.evaluate --phase development
python -m experiments.evaluate --phase holdout
```

自動テスト: 9件の単体・結果整合性テスト、旧JS/Python 360ケース、更新画面/Python 1680ケース（到達・囮応答・切替・手数と行動履歴）、画面で70000エピソードの比較と不正シードを確認。CIにも登録。画面テストはNodeの模擬DOMであり、実際のiPhone Safari、描画、タッチ、ファイル保存ダイアログは未検証。横幅制約、44px操作領域、分割実行、中止、シード明示、JSON保存を実装した。

## 次の研究課題

固定A以外の固定配置とラベル回転、複数の独立乱数系列、より多い入口、標的の移動、偽の応答、複数段階の探索、移動費用、囮識別誤りを追加し、検証計画を新しく分離する。スコア予測だけでは標的の保護価値と切替コストを考慮できない。今回失敗した条件を次回の開発に使う場合、別の未使用検証条件を用意する必要がある。実システムや外部サービスへの接続はこの実装の対象外。
